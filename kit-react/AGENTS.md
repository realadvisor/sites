# AGENTS.md (React Router): the files, imports and code of a React Router site

The framework half of the rules. The shared rules are in
`node_modules/@realadvisor/sites-kit-core/AGENTS.md` (read it first), the
design in `DESIGN.md` next to it. This file shows how a React Router 7 site
(framework mode, SSR on a Cloudflare Worker) does what they ask. Reference
sites: `examples/react/<name>` (studio-vey is the smallest complete one).

## Files

```
site.json                 country, locale, locales, developmentsPath, redirects (301s). Set it first.
vite.config.ts            cloudflare() + reactRouter() + sitesKit(). Keep sitesKit() in plugins.
react-router.config.ts    ssr: true. Keep it.
wrangler.jsonc            Worker config (main: workers/app.ts). No secrets here.
workers/app.ts            createSiteWorker(): env, 301s, CSP nonce, security headers. Keep it.
app/entry.server.tsx      The kit's renderer (nonce, whole page before answering). Keep it.
app/entry.client.tsx      Hydration, for routes that ask for it (Scripts below). Keep it.
app/root.tsx              Document shell: <head>, kit settings, ConsentBanner, KitScripts, ErrorBoundary (404/410 page).
app/routes.ts             Every URL: one route() per page. Add each new page here.
app/routes/*.tsx          Pages: a loader (server data) + a component. The template's are bare wiring examples: replace their markup.
app/routes/api.enquiry.ts POST endpoint behind EnquiryForm. Keep it.
app/routes/legal.tsx, privacy.tsx  Legal notice and privacy policy, every language. Keep the content.
app/routes/sitemap.ts, robots.ts   Keep; add new static pages to STATIC_PATHS.
app/routes/404.tsx        The not-found page (404 and 410) and the splat route.
app/components/Layout.tsx The site layout: SEO head, header, footer. Every page renders inside it.
app/client.ts             The site's one browser script: kit(), the site's behaviours, islands().
app/lib/data.server.ts    THE data client (`sites`) and agency(). Server only.
app/data/fixture.json     Fixture data (dev, build). Production reads live data.
app/styles/               global.css (tokens, base) and the site's shared CSS.
```

## A page: loader + component

```tsx
// app/routes/listing.tsx (route('listings/:slug', 'routes/listing.tsx') in app/routes.ts)
import type { Route } from './+types/listing';

export async function loader({ params, request }: Route.LoaderArgs) {
  const listing = await sites.listing(params.slug);
  if (!listing) throw notFound(!!listingIdFromSlug(params.slug)); // 404, or 410 for a listing that left
  return { listing };                                              // only what the page renders
}

export default function Page({ loaderData: { listing } }: Route.ComponentProps) {
  return (
    <Layout title={…} description={…} image={listing.photos[0] && img(listing.photos[0].url, { w: 1200, h: 630 })}
      jsonLd={listingJsonLd(listing, pageUrl)}>
      <h1>{listing.title}</h1>
      …
    </Layout>
  );
}
```

- **Data only in loaders**, through `sites` (or the template's `agency()`).
  A loader runs on the server for every request: that is the "render on
  request" of the shared rules. No `clientLoader`, no `prerender` in
  react-router.config.ts, no `headers` export with Cache-Control.
- Never import `app/data/fixture.json` or a `*.server.ts` file into a
  component or `app/client.ts`: Vite would put the whole fixture into the
  browser bundle (check:deploy's secret scan reads it). Fixture-only fields
  are read in the loader and returned.
- **Not found**: `throw notFound()` (404) or `throw notFound(true)` (410)
  from the loader; the root `ErrorBoundary` renders `routes/404.tsx` with
  that status. In the 404 page read 410 with `useGone()`, never a prop
  (React Router drops the props of a route's default export). The splat
  route (`route('*', 'routes/404.tsx')`) answers every unknown path.
- A loader that throws anything else gives the short 500 page
  (`ServerError` in 404.tsx); the Worker logs it.
- Every page renders `<Layout>` (title, description, image, jsonLd,
  noindex, alternates). The layout renders `<Seo>` with the canonical URL;
  `<JsonLd>` for any other JSON-LD. React 19 hoists the tags into `<head>`.
- Lists in JSX need a `key`. A number and its label are separate words:
  JSX drops the space between inline elements on two lines, so write
  `<strong>{n}</strong>{' '}<span>rooms</span>`.

## HTML from data

```tsx

{listing.description && <SafeHtml className="prose" html={sanitized(listing.description)} />}
```

`dangerouslySetInnerHTML` only as `{{ __html: sanitizeHtml(...) }}` written
inside it; anything else fails check:deploy. JSON-LD only through `<Seo
jsonLd>` or `<JsonLd>`.

## Listings search

```tsx
export async function loader({ request }: Route.LoaderArgs) {
  return { pool: await sites.allListings(), params: parseSearch(new URL(request.url).searchParams) };
}
export default function Page({ loaderData: { pool, params } }: Route.ComponentProps) {
  const result = searchListings(pool, params);
  return (
    <Layout title={…} description={…}>
      <h1 data-rs-sync="h1">{heading}</h1>
      <ListingsSearch result={result} contactHref="/contact" valuationHref="/contact#valuation">
        {(l, i) => <ListingCard listing={l} priority={i === 0} />}
      </ListingsSearch>
    </Layout>
  );
}
```

A page that the search script updates (`ListingsSearch`) stays static (no
hydration). Two search pages (`/buy`, `/rent`): one shared component, two
routes, each with its own pool (`allListings({ offer_type: 'buy' })`) and
`base` (studio-vey's `kaufen` / `mieten`).

## Scripts: static by default

Every route is server-rendered HTML plus **one** bundled browser script,
`app/client.ts`, which `<KitScripts>` loads with the request's CSP nonce:

- `kit()` loads each kit part (enquiry, consent, combobox, search, map)
  only on a page that has it.
- The site's own small behaviours (menu, tabs, gallery, lightbox,
  accordions) are plain functions in `app/client.ts` that find their
  elements by `data-*` attributes and run on every page (studio-vey: menu,
  offer tabs, gallery, about 5 KB). This is the default: **no React in the
  browser**, so `onClick`, `useState` and `useEffect` in a page do nothing.
- **Islands** (opt-in, real React interactivity only: a configurator, a
  calculator): `<Island name="Calc" component={Calc} props={…} />` renders
  it on the server; `islands({ Calc: () => import('./islands/Calc') })` in
  `app/client.ts` hydrates it alone and loads React (~90 KB) only on a page
  that has one. Props are JSON; never import server code into an island.
- **Hydrated route** (rare: a page that is an app): `export const handle =
  { hydrate: true }`; React Router's scripts then render, all with the
  nonce, and `app/entry.client.tsx` runs `./client` too.

Never an inline `<script>`, `on*=` string attributes, `<script
dangerouslySetInnerHTML>` or a script from another host: check:deploy
fails every script without the response's nonce.

## Languages

`locales` in site.json (default first, the others under `/fr/…`,
`/en/…`). Each language's URL is its own `route()` to the same module with
its own `id` (`route('en/homes', 'routes/units.tsx', { id: 'units-en' })`);
the template's `:lang/legal` and `:lang/privacy` routes cover the legal
pages. The page's locale comes from its path: `usePageLocale()` in
components, `pageLocale(request)` in loaders. `<html lang>`, `Seo`,
`ConsentBanner`, `EnquiryForm` and `ListingsSearch` default to it. Example:
`examples/react/casa-de-les-rajoles` (Spanish + English).

## CSS

`import './styles/global.css'` in root.tsx **before** the kit's
`import '@realadvisor/sites-kit-react/styles/kit.css'`, so the kit's
defaults stay below the site's at equal specificity. A component or page
imports its own stylesheet (`import './ListingCard.css'`); scope it by a
class on its root element (`.listing-page .facts { … }`): there are no
scoped styles. Theme the kit's parts with their tokens, never by restating
their values. `sitesKit({ inlineCss: true })` (the template's) inlines each
page's CSS into `<style>` (no render-blocking request).

## Images

`<RaImage src={photo} width height sizes alt priority? mobile? />`: resized,
srcset, lazy; `priority` on the LCP image (it alone gets AVIF). `style` is
an object (`style={{ maxWidth: '100%' }}`); `data-*` attributes go on the
`<img>`.

## Commands

Same as the shared table: `pnpm dev` (react-router dev on :4321), `pnpm
check`, `pnpm screenshot`, `pnpm fixture`, `pnpm kit test map`, `pnpm
check:deploy` (`sites-kit-react check deploy`: builds, serves `build/` with

files).

## Do not (React Router)

- Remove `sitesKit()` from vite.config.ts, edit `workers/app.ts`,
  `app/entry.server.tsx` or `app/entry.client.tsx`, or set `ssr: false`.
- Add `<Scripts />` or `<ScrollRestoration />` yourself (`<KitScripts>`
  decides) or a `nonce` of your own. Links are plain `<a href>`: pages are
  full page loads on static routes.
- Use `react-helmet`, a UI kit, Tailwind, CSS-in-JS or a state library.
